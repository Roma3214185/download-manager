# Менеджер завантажень

Лабораторна робота 2 «Багатопотокове програмування в графічному
інтерфейсі»: Swing-застосунок з п'ятьма незалежними завантаженнями,
кожне з яких виконується в окремому потоці.

Весь код — у [DownloadManagerFinal.java](src/main/java/downloadmanager/DownloadManagerFinal.java).

## Що вміє

- 5 завантажень, у кожного прогрес-бар, кнопки «Старт» / «Скасувати» і статус.
- Кожне завантаження працює у своєму потоці, вікно не зависає.
- «Загалом завантажено: X МБ» — спільний лічильник, `synchronized (lock)`.
- «Активних завантажень: X з 5» — окремий лічильник з окремим замком
  `activeLock`: +1 на початку потоку, −1 у `finally` (і при завершенні,
  і при скасуванні).
- «Скасувати» ставить прапорець і перериває потік — він зупиняється
  одразу, навіть посеред `sleep`.

## Запуск

**IntelliJ IDEA:** File → Open → папка проєкту (підтягнеться як Maven),
відкрити `DownloadManagerFinal` і натиснути ▶ біля `main`.

**Термінал** (JDK 21+, Maven):

```bash
mvn package
java -jar target/download-manager-1.0.0.jar
```

## Відповіді на контрольні питання

1. **Чому кожне завантаження — в окремому потоці?**
   Щоб завантаження йшли одночасно й незалежно, і щоб жодне з них не
   займало EDT. Один спільний потік виконував би їх по черзі.

2. **Чому довга операція в `ActionListener` «вішає» GUI?**
   `ActionListener` виконується на EDT. Поки він не повернеться, EDT не
   обробляє інші події: не перемальовує вікно, не реагує на кліки.

3. **Що таке EDT?**
   Event Dispatch Thread — єдиний потік Swing, який обробляє події
   (кліки, клавіші) і малює компоненти. Swing не потокобезпечний, тому
   змінювати компоненти можна тільки з EDT.

4. **Навіщо `SwingUtilities.invokeLater()`?**
   Фоновий потік не може сам змінювати GUI. `invokeLater` кладе завдання
   в чергу EDT, і EDT виконує його, коли звільниться. Так прогрес-бари й
   мітки оновлюються безпечно.

5. **Що тут спільний ресурс і чому синхронізація?**
   Лічильники `totalDownloaded` і `activeDownloads` — їх одночасно змінюють
   кілька потоків завантаження. Без синхронізації частина оновлень
   загубилася б.

6. **Що таке race condition і як допомагає `synchronized`?**
   Ситуація, коли результат залежить від порядку виконання потоків.
   `total += x` — це «прочитати, додати, записати»: два потоки можуть
   прочитати одне значення, і одне додавання пропаде. `synchronized`
   пускає в блок лише один потік за раз, тож операція стає неподільною,
   а зміни видимі іншим потокам.

7. **Як скасувати завантаження без блокування GUI?**
   Кнопка лише ставить прапорець `cancelled[i]` (`AtomicBoolean`, видимий
   між потоками) і викликає `interrupt()`. Потік сам перевіряє прапорець
   (або отримує `InterruptedException` зі `sleep`) і завершується. EDT
   нічого не чекає, тому вікно не зависає.
